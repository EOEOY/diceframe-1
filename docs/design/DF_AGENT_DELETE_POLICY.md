# DF Agent 内容纠错、撤销与删除策略

状态：用户已批准，第一阶段已接入。支持资料册/条目启停、版本检查的内容撤销、有限归档与恢复，以及开局后修改本局资料来源。

## 当前代码事实

- `assistant_authoring.py` 的内容编辑通过 owning service 记录修改前后的快照；`assistant_recovery_tools.py` 注册启停、归档、撤销与恢复工具。资料册条目修改作为同一 SQLite 事务提交，整批成功或回滚。
- `assistant_agent.py` 已对修改保存服务器执行计划，要求 owner 确认；计划绑定会话、参数摘要、资源状态与有效期。确认前状态变化会要求重新计划，重复确认复用执行记录，结果不确定的写操作禁止盲目重放。
- `lorebook_operations`（Lorebook schema v10）保存 owner 私有的操作和 canonical 快照。只有本次接入后经这些路径记录的编辑、启停及归档可以恢复；历史编辑、草稿创建的新世界/冒险/角色不自动补造快照。
- 世界简介及角色叙事编辑先持久化 prepared 记录，再调用其 owning writer，写入后记 applied；跨文件和数据库不声称原子事务。结果不确定时保留 prepared / recovery_required，拒绝盲目重放。只恢复本次触及的叙事字段，不回退世界设定全文、规则、属性、资源、回合或已确认剧情。
- `invoke_plugin_tool` 仅允许描述符明确声明 `agent_effect=read_only` 的工具，仍需确认；未知、mutation、destructive 工具转到手动插件流程。声明不是原生插件进程的沙箱或行为证明，宿主权限边界继续有效。
- 插件作者可以通过 Python 3.10 兼容的 `ToolRuntime.tool(agent_effect="read_only")` 显式声明；未声明的旧工具仍可走原手动插件流程，不猜测其影响类型。

## 用户入口

- 开局后：**GM 工作台 → 场景 → 本局资料册**。最多选择 16 本可编辑来源，预览后确认，仅替换本局的 game 绑定与 portable refs；角色来源保持锁定，世界/全局绑定和其它对局不改写。已停用的资料册不能选入。
- 撤销/回收站：**内容 → 资料册 → 内容撤销 / 回收站**。查看当前 owner 最近的内容操作，按服务器 operation ID 预览、确认撤销或恢复。已撤销、已恢复和结果待核实记录明确显示状态；prepared 不提供重复执行按钮。
- DF Agent 可以读取本局实际资料来源、设置本局选书、读取自己的恢复记录并提出启停/归档/撤销/恢复计划；无需把快照正文交给模型或客户端。

## 产品路径

1. 未保存的 AI 草稿允许直接编辑或丢弃。用户不满意时先改草稿，不产生持久化清理操作。
2. 已保存但写错的条目，优先更正、停用或取消本局引用。停用整本资料册会影响所有引用它的对局；仅本局不用应操作本局绑定，确认卡必须显示影响范围。
3. 内容修改支持“撤销上一项内容操作”。只撤销服务器记录中由该 owner 确认的目标和变更，不能凭名称、`agent_` ID 前缀、模型记忆或模型提供的备份判断所有权。
4. 需要移除内容时先移入可恢复的回收站，展示恢复入口。永久清空保留给用户手动操作，Agent 没有 purge、删除文件或任意 SQL 能力。

## 执行限制

- 只允许自建内容或明确创建的用户副本。内置/插件源文件、主资料册、系统规则、凭据与应用设置不提供 Agent 删除工具。
- 每次显式列出 canonical 目标、名称、条目/绑定数量、引用的对局和恢复方式。整世界/整本书与单条目使用不同操作，不把“删掉错误内容”解释成清空全部。
- 第一阶段单次至多处理 10 个指定条目，不接受通配符、模糊匹配后的全量删除或跨库批量清空。需要更多时拆为可审核的明确批次。
- 内容仍被对局或角色引用时，先展示影响并由用户处理引用；正在使用的世界、角色和冒险不允许 Agent 直接移除。取消某局引用不改变其它局的引用。
- 修改、停用、恢复、归档和撤销都通过现有延迟审批机制；模型只提出候选，服务器校验拥有派发权。普通界面的恢复/本局选书使用同一服务端计划与确认接口，无需付费模型。未知或破坏性插件工具不可绕过限制。
- 整册归档仅支持不超过 10 条目的自建非主资料册，且不得有对局/角色引用、插件源条目或外部条目连接。单次条目归档/启停最多 10 个明确 ID；不提供世界、角色、冒险、存档的删除或归档工具，不提供永久清空。

## 撤销与恢复必须具备的契约

- 由内容 owning service 在修改前持久化目标身份、受影响字段的 before/after、原始版本和引用摘要，再执行事务；缺失可靠快照时不执行需要可恢复保证的操作。
- 日志和快照属于 owner 私有数据，包含 GM 资料时不能进入公开页、普通日志或不必要的模型上下文。客户端只传服务器 operation ID 和确认意图。
- 撤销前重新读取 canonical 内容，验证当前仍对应该次操作的 after 版本。人工或其它 Agent 后续编辑过时，拒绝自动覆盖并提示重新审查。资料册比较版本/绑定及目标条目；世界/角色比较 owning 文件版本，检查较保守，同册或同卡片库其它编辑也可能阻止撤销。本阶段不提供自动冲突合并或差异编辑器。
- 撤销修改只恢复该次操作触及的字段；撤销新增前验证对象未被后来编辑或引用。不用整库/整目录回滚覆盖不相关内容。
- 执行记录需支持重启恢复、重复确认返回原结果和失败补偿。派发后结果不确定时沿用 `recovery_required`，不盲目重放。
- 这里只纠正创作内容。已经确认的剧情、世界事实、角色机械状态、骰点和存档回合继续由现有 authority 管理，不随内容撤销回退。

## 实现与验收

内容恢复由 `content_recovery.py` / `content_metadata_recovery.py` 负责，存储快照与碰撞安全恢复由 `lorebook/operations.py` 负责；`game_lorebooks.py` 负责本局引用更新、保存与有状态检查的补偿。路由和 WebAPI 仅作门控与委托。正常重启加载 Python 模块和 v10 迁移，不改现有条目与存档结构。

验收覆盖 owner/会话隔离、审批参数伪造、误选范围、批量上限、内置/插件/主册保护、活动引用、快照失败、人工后续编辑冲突、跨书条目身份、并发/重复确认、重启后不确定结果和 GM 私密资料隔离。

真实 WebAPI 与存档/资料库验收使用可控模型响应，覆盖编辑 → 确认 → 撤销、真实磁盘重载后选书与执行记录、机械字段不变。桌面与手机端覆盖本局选书确认/刷新、条目停用撤销、归档恢复和私密正文不进入恢复列表；自动测试不访问付费模型。

本次收尾验收：后端相关回归 265 项、前端定向回归 79 项、桌面/手机端到端 4 项通过，类型检查与生产构建通过。前端端到端还覆盖审批后人工编辑的冲突提示与取消，不覆盖后续人工内容。模型响应采用测试替身；原生插件不通过声明获得额外权限。
